Getting started

From nothing to a first scan in about five minutes.

Before you start

  • Docker must be installed and running. Night Owl runs each engine from a pinned container image. (An engine already on your PATH is used instead, unless you pass --container.)
  • macOS or Linux for the one-line installer. On Windows, download the .exe from the releases page. Windows and Linux binaries are built by CI but have not yet been run by hand, see known limits.
  • Git (optional) enables scanning of secrets in history and "new code only" gates.

1. Install

curl -fsSL https://raw.githubusercontent.com/finepointcgi/Night-Owl/main/scripts/install.sh | sh

The installer picks the right binary for your OS and CPU, downloads it, and verifies its SHA-256 checksum against the release's SHA256SUMS before installing. It installs to ~/.local/bin and tells you if that folder is not on your PATH.

VariablePurpose
NIGHTOWL_VERSIONInstall a specific version, for example 0.1.1.
NIGHTOWL_INSTALL_DIRInstall somewhere else.
NIGHTOWL_REPOInstall from a fork (owner/repo).

Prefer building from source? You need the .NET 10 SDK:

git clone https://github.com/finepointcgi/Night-Owl
cd Night-Owl
dotnet run --project src/NightOwl.Cli -- scan path/to/project

2. Your first scan

nightowl scan path/to/project

The first run is slower because engine images are pulled once (and Night Owl's own images are built). Later scans reuse them.

You will see:

  1. A list of engines that ran and any warnings (an engine that fails is reported as a warning; the others still finish).
  2. A table of findings: severity, category, location, and a short description.
  3. Project totals (complexity, duplication, coverage, when available).
  4. A gate result, and which findings were not gating (see below).

3. Reading the results

Exit codes

CodeMeaning
0Scan finished and every gate passed.
1A gate failed (for example a high-severity finding in production code).
2Error: Night Owl itself could not complete.

4. Choosing an output

nightowl scan . --format json --output report.json
nightowl scan . --format sarif --output results.sarif
nightowl scan . --format markdown --output summary.md

Formats: table (default), json, sarif (for GitHub code scanning and many IDEs), markdown (for PR comments), and codeclimate (GitLab merge request widget). You can write several at once with --sarif-output, --summary-output and --codeclimate-output.

5. Dealing with a finding

Suppose the scan reports a finding you've decided is not a real problem:

nightowl triage <id> false-positive --reason "Value is a constant, never user input"

Other states: accepted-risk (add --expires 2027-03-01 so it comes back for review), confirmed, fixed, reset. Add --shared to store the decision in .nightowl/triage.json inside the repo so teammates and CI see it too.

6. The dashboard (optional)

dotnet run --project src/NightOwl.Web

A web UI over your saved scans: every project, findings by severity, a trend chart, triage buttons, and daily re-checks for new advisories while it runs. It listens on localhost; to expose it to a network you must set NIGHTOWL_DASHBOARD_TOKEN (it refuses to start otherwise).

Where things are stored

Reports, SBOMs, triage decisions, caches and the installed engine manifest live in ~/.nightowl (change it with NIGHTOWL_HOME). Nothing is written into the repository you scan, except the files you create under .nightowl/ (policy.yml, ignore, shared triage.json).
