FAQ and troubleshooting

Quick answers, then the honest list of what Night Owl does not do yet.

Frequently asked

Do I need Docker?

Yes, unless you've installed the engines yourself and put them on your PATH. By default each engine runs from a pinned container image so everybody gets the same results.

Does my code leave my machine?

No, scans run locally. Only dependency names and versions go to OSV.dev. AI features are opt-in; --ai ollama is fully local.

Why did the scan pass when I can see findings?

Most likely they are in tests, examples or docs, which don't fail the gate by default. Look for the Not gating: line. Use --include-context all to gate on everything. See Policy and gates.

Why does a finding keep coming back after I marked it a false positive?

Triage is keyed to the fingerprint, which includes the rule, file and normalized snippet. If you rewrote the flagged code, or moved it to another file, it is a different finding. Mark it again. Use --shared so the decision is saved in the repo.

The same problem appears twice.

Identical findings from different engines are merged by fingerprint. When a pattern rule and a taint rule describe the same bug on the same line (for example a shell call built from request data), Night Owl keeps the taint finding and folds the pattern rule into it: you'll see its rule id and CWE listed as aliases, and the severity is the worse of the two. Unrelated findings on one line (a weak hash beside an injection) are never merged. One side effect: a triage decision you made on the pattern finding no longer matches, because that finding's id was absorbed. Triage the surviving finding once.

A secret was reported in git history, but I deleted it.

Deleting the line doesn't remove it from history; anyone with a clone can read it. Rotate the credential. That is the fix.

Can I turn off automatic updates?

NIGHTOWL_AUTO_UPDATE=0 or --no-update.

Troubleshooting

SymptomLikely cause and fix
"Cannot connect to the Docker daemon"Start Docker Desktop (or the Docker service). Night Owl needs it for engines.
Image pull fails with HTTP 429Docker Hub rate limit. Night Owl retries through mirror.gcr.io automatically; just run again.
First scan is very slowImages are being pulled and built once. Later runs are fast.
"nightowl: command not found" after install~/.local/bin isn't on your PATH. Add it, or set NIGHTOWL_INSTALL_DIR.
Policy error mentioning an unknown keyTypos are errors on purpose. Run nightowl policy validate to see which line.
"Signature check failed. The manifest was not installed."The downloaded engine manifest failed a signature, digest, schema or rollback check. Night Owl keeps your current engines. Don't bypass it; report it.
Canary failed after an updateNight Owl restored the previous manifest by itself and will skip the bad one. Nothing to do. Run nightowl canary to confirm.
Scan finds nothing in an obviously vulnerable projectCheck the warnings at the top: an engine may have failed and been skipped. Re-run with --engines to isolate it.
Exit code 2An error in Night Owl itself, not a gate failure. Read the message printed above the summary.

Known limits

These are real, and worth knowing before you rely on it.

  • Not a Coverity replacement for deep C/C++. cppcheck finds common serious defects; whole-program interprocedural analysis is not matched by open source.
  • No binary or snippet matching. That is Black Duck's main advantage and is not chased here.
  • Reachability looks at imports only, not whether the vulnerable function is called.
  • Windows and Linux binaries are built by CI but haven't been run by hand yet. macOS is verified end to end (install, update, self-update).
  • Single signing key, no rotation. See the signing key.
  • Some noise remains: framework code that implements a sink itself (such as express's own res.send) is flagged; Flask's lockfile reports CVEs in dev-only tools.
  • The VS Code extension has only had a syntax check.
  • fix doesn't cover Maven or Cargo yet.

Roadmap

The full prioritized list is docs/BACKLOG.md. The headline items:

  1. Less noise: merge duplicate findings, add a confidence field, tune rules against real repositories.
  2. Fingerprints that survive renames, with a regression corpus so changes never silently re-open triaged findings.
  3. Wider auto-fix: Maven, Cargo; warn on major-version jumps.
  4. Depth: a second C/C++ engine, cognitive complexity, symbol-level reachability for Go.
  5. Experience: a tested VS Code extension, bulk triage, an organization-wide dashboard.
  6. Trust: multi-key signing, provenance (SLSA) for releases and SBOMs.
  7. Distribution: Homebrew and Scoop packages.

Contributing

Adding an engine is one class implementing IEngine plus one entry in engines/engines.json. Before opening a PR run dotnet test; CI additionally runs the canary check against every engine. Questions and bugs: open an issue.
