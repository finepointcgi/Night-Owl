Configuration reference

Every file Night Owl reads or writes, every key you can set, and where each one lives. If you only want the common cases, see Policy and gates.

Where everything lives

LocationWho writes itCommit it?Purpose
.nightowl/policy.yml in your repoyouyesGate thresholds, license rules, quality limits
.nightowl/ignore in your repoyouyesPaths whose findings are dropped

Night Owl never writes into the repository you scan, apart from files you ask for (policy init, triage --shared, hook install).

licenses.reviewlist of SPDX idsGPL-2.0 and 3.0, LGPL-2.1 and 3.0 (all -only/-or-later forms), MPL-2.0, EPL-2.0, CDDL-1.0A match is a medium finding. Replaces the default list.

quality.max-complexitynumber15Cyclomatic complexity per function.

Strict by design. An unknown key, a bad value or a wrong type is an error that stops the run, never silently ignored. Run nightowl policy validate after every edit; it prints exactly what will apply.

Precedence

  1. Command-line flags win. An explicit --fail-on replaces the whole gate, including per-category rules, because a flag is a deliberate one-off.
  2. policy.yml comes next.
  3. Built-in defaults apply last: fail on high, production code only, complexity 15.

A complete, realistic policy

version: 1

gate:
  fail-on: high
  per-category:
    secret: low             # a secret of any severity blocks
    infrastructure: medium  # misconfigured Terraform blocks earlier
    quality: none           # complexity and duplication never block
  ignore-unimported: true   # skip CVEs in packages no code imports
  include-contexts: [test]  # a real key in a test folder still blocks

licenses:
  deny:   [AGPL-3.0-only, AGPL-3.0-or-later, SSPL-1.0]
  review: [GPL-3.0-only, LGPL-3.0-only, MPL-2.0]
  flag-unknown: true

quality:
  min-coverage: 70
  max-duplication: 5
  max-complexity: 15

.nightowl/ignore

One pattern per line, gitignore style. Findings in matching paths are dropped from the report, unlike a context label (which keeps the finding listed).

PatternMatches
# commentNothing (comment). Blank lines are skipped.
*.min.jsAny file with that name, in any folder (no slash means "match the name anywhere").
legacy/The legacy folder and everything under it, wherever it appears at the start of a path.
src/gen/*.csFiles directly inside src/gen (a slash anchors the pattern to the project root). * never crosses a folder.
docs/**/draft.mddraft.md at any depth under docs, including directly in it. ** crosses folders.
file?.js? matches one character.

Ignore hides, context labels don't. Use ignore for code you will never fix (deliberately vulnerable samples). For tests and examples, prefer the automatic context labels: those findings stay visible and can still be gated on request.

.nightowl/triage.json

A JSON array, sorted by finding id so diffs stay small. Hand-editing is fine, but nightowl triage is easier.

FieldMeaning
findingIdThe finding's fingerprint.
stateconfirmed, false-positive, accepted-risk, fixed.
reasonWhy. Always fill this in; it is what the reviewer reads.
by, atWho decided and when.
expiresOptional. After this moment an accepted risk counts again and needs a fresh decision.
titleThe finding's title at decision time, so the file is readable in a code review.

There are two layers: shared (.nightowl/triage.json in the repo) and local (~/.nightowl/triage/<project>.json). If both decide the same finding, shared wins.

Pen-test scope file

Created by nightowl pentest init. It is JSON (comments and trailing commas allowed). Unknown fields are rejected, so a typo can't weaken a limit.

FieldDefaultMeaning
authorization.ownerrequiredPerson or team that owns the target and approved the test.
authorization.referencerequiredTicket, contract or rules-of-engagement id. Recorded in every report.
authorization.expiresrequiredISO date-time. After it, the scope stops working. The template sets 7 days.
targetsrequiredBase URLs allowed (https://staging.example.com). Scheme, host and port must match exactly. No wildcards.
include["/"]Path prefixes that may be requested.
exclude[]Path prefixes that must never be requested. Wins over include. Prefix match: /logout also blocks /logout.php.
methodsGET, HEAD, OPTIONSAdd POST etc. only deliberately.
maxRequestsPerSecond10Enforced by the proxy.
timeBudgetMinutes30Whole-run time limit.
auth.header, auth.valueFromEnvnoneHeader name and the name of the environment variable holding its value. The value itself is never in the file.
allowActiveScanfalseLets ZAP send attack payloads to API operations.
{
  "authorization": {
    "owner": "Platform security team",
    "reference": "SEC-1234",
    "expires": "2026-12-01T00:00:00Z"
  },
  "targets": ["https://staging.example.com"],
  "exclude": ["/logout", "/account/delete"],
  "maxRequestsPerSecond": 5,
  "auth": { "header": "Authorization", "valueFromEnv": "NIGHTOWL_AUTH" }
}

Inside ~/.nightowl

PathContents
manifest.jsonThe installed, signature-verified engine manifest (the "lockfile" for all scans).
manifest.previous.jsonThe manifest before the last update, kept for rollback.
rejected-sequencesSequence numbers that failed the canary. Never installed again.
last-update-checkWhen Night Owl last asked for a new manifest.
reports/Saved scan reports, SBOMs, and history/*.jsonl (the trend data).
triage/Local triage decisions, one file per project.
cache/Engine caches, such as Trivy's vulnerability database.
pentests/Request logs from active tests (*.requests.jsonl).

It is safe to delete cache/; engines refill it. Deleting manifest.json returns Night Owl to its built-in engine versions until the next nightowl update.

engines/engines.json (for maintainers)

The single source of truth for engine versions. The release pipeline turns it into the signed manifest.

FieldMeaning
name, binaryEngine name, and the executable looked for on PATH.
imageContainer image without a tag.
buildFolder with a Dockerfile, for engines Night Owl builds itself; null for engines with an official image.
upstream[]Where new versions come from: repo, current tag, a version template, and the dockerfile whose pins the watch bot rewrites.
versionThe version that ships.

Version templates: {tag} is the upstream tag, {bare} is the tag without a leading v, asset-sha256:NAME is the hash of a release asset, tarball-sha256 the hash of the tag's source tarball, and FROM means "rewrite the Dockerfile's FROM line".

The signed manifest

FieldMeaning
schemaVersionCurrently 1. Unknown versions are refused.
channelFor example stable.
sequenceA number that only goes up. Lower numbers than installed are refused (rollback protection).
publishedWhen it was signed.
engines[]Per engine: name, version, image, and an immutable image digest (sha256:…) that signed manifests must have.
nightOwlLatest release: version and, per platform, a url and sha256 (platform names such as linux-x64, osx-arm64, win-x64).
