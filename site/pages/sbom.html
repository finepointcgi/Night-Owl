SBOM, monitoring and fixes

Know what you ship, hear when it becomes vulnerable, and fix it with one command.

SBOM and VEX

A software bill of materials lists every component in your software. A VEX document says which known vulnerabilities actually affect you. Customers and regulators increasingly ask for both.

nightowl sbom . --format cyclonedx --output sbom.cdx.json
nightowl sbom . --format spdx --output sbom.spdx.json
nightowl sbom . --vex --output sbom.vex.json

With --vex, the CycloneDX file gets a vulnerabilities section whose states come straight from your triage decisions:

Reachability: is the vulnerable package even used?

Many dependency CVEs sit in packages your code never imports. Night Owl checks whether any first-party file imports the package (npm, PyPI, Go, NuGet). If none does, the finding is marked [not imported directly] and shown that way in the dashboard.

It's a hint, not proof. The package may still arrive through another dependency, and "imported" does not mean "the vulnerable function is called". So --ignore-unimported only removes those findings from the gate, never from reports. Symbol-level reachability is on the backlog.

Continuous monitoring

New CVEs are published every day, long after you last scanned. Every scan saves the SBOM, and:

nightowl monitor --webhook https://hooks.slack.com/... --fail-on high

asks OSV.dev about every saved dependency. When a new advisory affects something you already ship, it's added to the report and posted to your webhook (Slack, Teams, Discord, Mattermost). The running dashboard does the same check daily. Only package names and versions are sent.

Automatic fixes

nightowl fix . --dry-run    # show the plan
nightowl fix . --pr         # commit to a branch and open a pull request

For each vulnerable dependency, Night Owl picks the smallest version that fixes all of its advisories. It first checks that version against OSV, and moves higher if the target has advisories of its own.

EcosystemHow it updates
npmLockfile-only, install scripts disabled; uses overrides for transitive dependencies
NuGetPackage references
piprequirements*.txt pins
GoGo modules
Composercomposer.json requirement edited in its own style; lockfile synced with composer update --no-install

Maven and Cargo are not supported yet.

Trends over time

Every scan appends a point to a per-project history (~/.nightowl/reports/history/*.jsonl). It is plain text on purpose, so there is no native database to ship. The dashboard shows open findings over the last scans, and what is new or resolved since the previous one.
