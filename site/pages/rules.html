Pattern rules versus taint rules

Take this code:

def run(cmd):                # not reachable from a request
    subprocess.call(cmd, shell=True)

@app.route("/x")
def x():
    subprocess.call(request.args["c"], shell=True)

A pattern rule flags both lines: both call a shell with a dynamic string. A taint rule flags only the second, because only there does request data arrive. Use pattern rules to find risky habits, and taint hits to decide what to fix first.

Taint rules understand sanitizers: wrapping the value in int() in Python, or parseInt in JavaScript, ends the flow, so no finding is raised.

Why schema statements get their own C# rule

A DROP DATABASE or CREATE TABLE built with string interpolation looks like SQL injection, but a database or table name can't be passed as a query parameter, so "use parameters" is advice nobody can follow. Night Owl reports those under nightowl.csharp.sql-ddl-interpolation at medium severity, with advice that fits (take the name from a fixed list or validate and quote it, and never from request data), and keeps the high-severity sql-injection-concat for data-manipulation statements where parameters do exist. It was added after scanning a real project, where a test-data loader tripped the old rule twice.

Writing your own rules

Night Owl uses Opengrep, which reads Semgrep-syntax rules. Put .yaml files in a folder and pass it with --rules:

nightowl scan . --rules ./my-rules

A minimal rule, forbidding a project-specific unsafe helper:

rules:
  - id: acme.no-unsafe-exec
    languages: [python]
    severity: ERROR
    message: acme.unsafe_exec() runs unvalidated commands. Use acme.safe_exec().
    pattern: acme.unsafe_exec(...)
    metadata:
      cwe: ["CWE-78"]

Custom rules run alongside the built-in pack, and their findings get the same fingerprints, triage, context labels and gate treatment as everything else. Rules passed with --rules make the Opengrep engine run even if the project's languages aren't in the built-in set.

Why Night Owl writes its own rules

The public Semgrep rule registry is licensed in a way that forbids bundling it in a competing product. Night Owl therefore ships its own rules, licensed Apache-2.0 and embedded in the binary. The pack is smaller than the registry on purpose: each rule is meant to have a high hit-rate, and the canary corpus contains samples for the main rule families so an engine update can't silently stop detecting them.
