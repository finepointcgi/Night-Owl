CI and editors

Catch problems at the three places that matter: while typing, before the commit, and on every pull request.

GitHub Actions

permissions: { contents: read, security-events: write, pull-requests: write }
steps:
  - uses: actions/checkout@v7
    with: { fetch-depth: 0 }
  - uses: finepointcgi/Night-Owl@v0.1.1
    with: { fail-on: high }

On pull requests the action:

  • fails only on new findings, not old debt,
  • updates a single summary comment (it doesn't add a new one on every push),
  • writes the job summary,
  • uploads SARIF so findings appear inline in the diff (code scanning), and
  • scans only the PR's commits for secrets, which is fast.

fetch-depth: 0 matters: "new findings only" and history scanning need the git history. If you have a .nightowl/policy.yml, leave fail-on out and the policy applies.

GitLab CI

Include the template from your .gitlab-ci.yml:

include:
  - remote: https://raw.githubusercontent.com/finepointcgi/Night-Owl/main/ci/gitlab/nightowl.gitlab-ci.yml

variables:
  NIGHTOWL_FAIL_ON: ""      # empty = use .nightowl/policy.yml (default high if there is none)
  NIGHTOWL_PATH: "."
  NIGHTOWL_ARGS: ""         # extra scan options

What it does:

  • Runs with Docker-in-Docker, because engines run as containers.
  • On merge requests, scans only changes since the MR's base commit (--since), so only new findings fail the job.
  • Findings appear in the merge request widget and diff through the code quality report (gl-code-quality.json).
  • Saves nightowl.md (a readable summary) and nightowl.sarif as job artifacts.
  • Runs on merge requests and on the default branch.

Before the commit

nightowl hook install

Adds a git pre-commit hook that scans the staged content (what you are about to commit, not your whole working tree) for secrets, and blocks the commit if it finds one. Bypass with git commit --no-verify if you must.

Using the pre-commit framework instead? The repository ships .pre-commit-hooks.yaml; add this repository to your .pre-commit-config.yaml and enable the nightowl-secrets hook.

VS Code

editors/vscode is a small extension that shows scan results as editor diagnostics (squiggles and the Problems panel).

It has had a syntax check but not a full manual test pass yet. Treat it as experimental. Planned: scan on save of just the changed file, quick-fix to triage from the editor, and a status-bar gate.

Protecting the dashboard

By default the dashboard listens on localhost only. If you configure it to listen on an address reachable from the network, it refuses to start unless NIGHTOWL_DASHBOARD_TOKEN is set to a long random value. People then supply the token as an Authorization: Bearer header or a cookie (a ?token= link also works on a first visit).

export NIGHTOWL_DASHBOARD_TOKEN="$(openssl rand -hex 32)"
dotnet run --project src/NightOwl.Web
