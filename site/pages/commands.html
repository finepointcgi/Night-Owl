Command reference

Every nightowl command. Square brackets are optional. Run any command with no arguments to see its usage.

nightowl scan

nightowl scan [path] [options]

Scans path (default: the current folder).

OptionWhat it does
--format table|json|sarif|markdown|codeclimateMain output format (default table).
--output fileWrite the main output to a file.
--sarif-output f --summary-output f --codeclimate-output fWrite extra formats in the same run.
--fail-on critical|high|medium|low|noneLowest severity that fails the gate. Overrides the policy file, including per-category rules.
--include-context test,example,docs,generated,vendored|allAlso let findings from those kinds of files fail the gate. Details
--since <git-ref>Gate only on findings in lines changed since that ref (and dependency versions introduced since).
--baseline <report.json|last>Gate only on findings not present in an earlier report. last uses your previous scan.
--ignore-unimportedExclude dependency findings for packages nothing imports from the gate (never from reports).
--min-coverage 80Fail if line coverage is below the percentage.
--max-duplication 5Fail if duplicated code exceeds this percentage.
--max-complexity 15Report functions above this cyclomatic complexity (default 15).
--image ref,refAlso scan these container images.
--image-include-unfixedInclude image vulnerabilities that have no fix yet.
--rules dirAdd your own Opengrep/Semgrep-syntax rules.
--history full|off|<range>Secret scanning of git history. full (default in a git repo), off, or a range like origin/main..HEAD. Options beginning with -- need the = form: --history=--since=2025-01-01.
--label v1.4.0Mark this scan as a release baseline in the dashboard, so change is measured since it. Done automatically when HEAD is exactly at a git tag.
--tags prod,team-aTag the project in the dashboard (see Projects and tags).
--engines a,bRun only these engines.
--containerAlways use the pinned container image, even if the tool is installed locally.
--no-updateSkip the daily engine-update check for this run.
--ai claude|claude-code|ollama --ai-model m --ai-min-severity s --ai-max nAI exploitability review. Details

Scan recipes

# Everything, human-readable
nightowl scan .

# Only the pull request's changes; fail on new high-severity problems
nightowl scan . --since origin/main --fail-on high

# Adopting on a legacy repo: only fail on problems that are new since last time
nightowl scan . --baseline last

# One scan, three outputs for CI
nightowl scan . --sarif-output nightowl.sarif --summary-output nightowl.md --codeclimate-output gl-code-quality.json

# Secrets only, fast (just the PR's commits)
nightowl scan . --engines gitleaks --history origin/main..HEAD

# Treat tests like production, and add your own rules
nightowl scan . --include-context all --rules ./my-rules

# Also scan a container image you build
nightowl scan . --image myorg/api:latest

# Quality gates
nightowl scan . --min-coverage 80 --max-duplication 5 --max-complexity 12

nightowl triage

nightowl triage <id> false-positive|accepted-risk|confirmed|fixed|reset --reason "..." [--expires date] [--shared]

Records a decision about a finding. --expires makes an accepted risk come back for review on that date. --shared writes to .nightowl/triage.json in the repository so everyone sees it.

Triage example

nightowl triage 0c6c902c7984c73f75bfb30259c967a0 accepted-risk \
    --reason "Internal-only admin tool, behind VPN" --expires 2027-03-01 --shared

nightowl policy

nightowl policy init        # write a commented starter .nightowl/policy.yml
nightowl policy validate    # check it and print exactly what will apply

nightowl sbom

nightowl sbom [path] [--format cyclonedx|spdx] [--vex] [--output file]

Writes a software bill of materials. --vex (CycloneDX) adds a vulnerability-status section built from your triage decisions. Details

nightowl monitor

nightowl monitor [--webhook url] [--fail-on high]

Re-checks every SBOM you've saved against OSV.dev for new advisories, and posts to a webhook (Slack, Teams, Discord, Mattermost) if you give one (or set NIGHTOWL_WEBHOOK).

nightowl fix

nightowl fix [path] [--dry-run] [--pr]

Upgrades vulnerable dependencies to the smallest version that fixes them. --dry-run shows the plan only. --pr commits to a branch and opens a pull request.

nightowl hook

nightowl hook install

Installs a git pre-commit hook that scans the staged content for secrets and blocks the commit if it finds one. Bypass in an emergency with git commit --no-verify.

nightowl pentest

nightowl pentest init
nightowl pentest <url> --scope nightowl-scope.json --i-am-authorized
        [--ai claude|claude-code|ollama] [--source path] [--openapi openapi.json]

Authorized testing of a running staging system. Details and guardrails

Updates and health

nightowl update          # fetch and install the newest signed engine manifest now
nightowl canary          # prove every engine still finds the known issues
nightowl self-update     # replace the nightowl binary with the newest verified release
nightowl engines         # list engines and versions
nightowl engines watch [--only base] [--write]   # find newer upstream engine/base-image versions

Environment variables

VariablePurpose
NIGHTOWL_HOMEWhere reports, caches and the manifest live (default ~/.nightowl).
NIGHTOWL_AUTO_UPDATE=0Turn off the automatic daily update check.
NIGHTOWL_WEBHOOKDefault webhook for monitor.
NIGHTOWL_AUTHExample name for the auth header value in an authenticated pen test (you choose the name in the scope file).
OLLAMA_HOSTWhere to find your local Ollama server for --ai ollama.
ANTHROPIC_API_KEYFor --ai claude.

Exit codes

These matter in CI, where a non-zero code stops the job.

CodeMeaningTypical CI response
0PassedContinue.
1A gate failedFail the job; show the findings to the developer.
2Error in Night Owl itselfFail the job, but treat it as an infrastructure problem, not a security result.
